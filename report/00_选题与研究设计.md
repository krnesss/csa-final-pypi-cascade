# 选题与研究设计：软件供应链的级联失效

> 课程：复杂系统分析 · 期末项目
> 选题：**Q4 开源软件生态中，一个底层包的漏洞会怎样"级联"到整个生态？**
> 本文件对应课程评价表的前三行：*选题（提出明确、可检验的问题）→ 建模（解释节点、边与简化假设）→ 分析（选择能回答问题的方法）*。
> 结果见 `03_结果.md`，讨论与局限见 `04_讨论与结论.md`。

## 1. 从现实现象到科学问题（对应课程"地铁站"案例的同一结构）

| 层次 | 地铁案例 | 本项目 |
|---|---|---|
| 01 现实现象 | 部分地铁站似乎格外重要 | 少数底层包（日志、加密、HTTP 客户端、序列化）一旦出问题，整个生态跟着遭殃（Log4Shell、`event-stream`、`xz` 后门……） |
| 02 研究问题 | 哪些车站失效会显著影响连通性？ | **一个底层包的漏洞，沿依赖链向上能传播多远、波及多少包、覆盖多少真实安装量？** |
| 03 科学假设 | 不同移除策略造成的影响不同 | 见 §3 的 H1–H4 |
| 04 分析方法 | 中心性分析、节点移除、连通性评价 | 有向依赖网络 + 级联可达性 + 多指标瓶颈识别 + 移除/修复情景仿真 + 保度序列零模型对照 |

**为什么这不是"泛泛介绍一个分析"**：题目里"影响会沿依赖链向上传播多远、波及多少包"
本身就是两个**可测量**的量（*深度*、*广度*），而"哪个包一旦失效影响面最大"
是一个**可排序**的问题；排序结果可以被**证伪**（见 §6 的检验 1–3）。这满足"明确、可检验"。

## 2. 研究对象与时间切片（先解决"数据是动态的"这一难点）

依赖关系是动态的，"抓哪一天"会决定结论。本项目用一个**可逐包重建**的方式定义切片：

```
时间切片 ≡ ( 下载量榜的统计月份 ,
             每个包在该次抓取中被解析到的具体版本号 )
```

* 下载量榜自带 `last_update` 字段（本项目用到的是榜单当月快照），直接记录；
* **每个包被解析到的具体版本号逐包落盘**（`universe_coverage.csv`、`closures.parquet`），
  因此"这一张网"可以在任何时候用同一批版本号重建，而不依赖"抓取那天"的实时状态。

这一点很关键：它让"固定一个时间切片"从一句口号变成可以审计的事实。

## 3. 网络模型：节点、边、权重、简化假设

### 3.1 节点

| 类别 | 定义 | 数量级 |
|---|---|---|
| 种子节点 S | 月下载量榜前 15,000 名（"人们在装什么"） | 15,000 |
| 叶子节点 T | 出现在种子包依赖闭包里、但不在榜上的包 | 数百 |

**为什么要把 T 也纳入**：如果只保留榜内包，任何"经由榜外包再往下"的依赖路径都会被切断，
级联广度会被系统性低估。我们把 T 纳入并对"图口径的截断误差"单独记账（见 `03_结果.md` §1.3）。

### 3.2 边

```
边 (u → v) 存在  ⟺  包 u 的直接依赖声明里包含包 v
```

* **方向**：依赖流方向（u 依赖 v）。
* **级联传播方向是反向的**：v 出漏洞 → 沿 v → u 传播到 u 的所有传递依赖者。
  这一点在报告里每次出现都要说清楚，否则"上游/下游"会全部说反。
* **只保留直接边**：deps.dev 返回的是**已解析闭包**（含 DIRECT/INDIRECT 标记）。
  如果我们把闭包里的间接关系全当作边，图会变成团状，所有中心性指标被压平、失去区分度。
* **自环剔除**；**不造权重**（见 3.3）。

### 3.3 权重与简化假设（必须显式声明的部分）

| 简化 | 我们怎么处理 | 会带来什么偏差 |
|---|---|---|
| 依赖强度 | **不加权**。deps.dev 不提供"用了多少"的信息，我们不臆造。 | 无法区分"仅 import 一次"与"深度绑定"，会**高估**弱依赖的影响 |
| 可选/条件依赖 | 只保留**无条件**直接依赖；`extra == '...'` 之类的可选依赖剔除 | 会**低估**"装了某个 extra 才触发的漏洞" |
| 版本 | 使用"每个包在该次解析中被解析到的具体版本"（已解析闭包），而非声明区间 | 这是本项目相对既有工作的**优势**（见 §5 实验三），但仍是"解析器的选择"，不是"每个用户实际装的" |
| 多版本共存 | 一个包只作为一个节点；不同解析上下文里的版本差异保留在闭包表中供实验三使用 | 合并了"同一包的多版本"，会**高估**共现，从而**高估**结构口径影响（这个偏差已被实验三量化） |
| 方法级可达性 | **不做到方法级**。版本脆弱 ≠ 代码真的调用了脆弱方法 | 我们的"版本感知影响"仍是**上界**，只是比"结构影响"紧得多。结论不得越过这条线 |
| 时间 | 单层、静态快照 | 结论只对这一个切片成立；用 §6 检验 2 做时间外推检查 |

## 4. 研究问题与可检验假设

**RQ0（结构）** 在这个切片上，PyPI 依赖网络的结构如何？
**RQ1（广度 / 深度 / 加权暴露）** 一个包出漏洞，级联能向上传播多远（跳数）、波及多少包、覆盖多少真实下载量？
**RQ2（瓶颈）** 哪些包"一旦失效影响面最大"？不同中心性指标给出的排名一致吗？哪个指标最能预测真实影响？
**RQ3（规则）** "凡依赖即受影响"（结构上界）与"依赖声明真的允许脆弱版本"（可实现影响）差多少？为什么差？
**RQ4（韧性情景）** "关键包被修复"与"关键包被移除"两种情景下，网络韧性怎么变？与随机、与保度序列零模型相比如何？

| 编号 | 假设 | 证伪条件（我们事先写下来，避免事后找理由） |
|---|---|---|
| **H1** | 级联影响面（广度）呈重尾，且暴露高度集中：少数包承担绝大部分"潜在波及量" | 若前 1% 的包承担的暴露 < 50%，或广度分布近似指数/对数正态而非重尾，H1 不成立 |
| **H2** | 拓扑中心性 ≠ 级联影响面。**传递依赖者数 / 反向 PageRank** 显著优于**介数**与**度** | 若介数与真实影响面的 Spearman ρ 与传递依赖者数相当（差 < 0.05），H2 不成立 |
| **H3** | 结构口径系统性高估，且高估倍数远大于 1；收缩机制是"依赖者早已解析到修复版本之后" | 若过近似倍数中位数 < 1.5，或"已修复比例"与高估倍数无关系，H3 不成立 |
| **H4** | 韧性强烈依赖**失效规则**：AND 规则（软件真实语义）下的崩塌远早于 OR 规则（食物网语义） | 若两种规则的 S(q) 曲线在 q ≤ 0.1 区间差异 < 5 个百分点，H4 不成立 |

> 写证伪条件是刻意为之：课程明确要求"结论是否超出证据"。事先声明"什么样算失败"，
> 是防止把任何结果都解释成支持假设的最有效办法。

## 5. 实验设计（每个实验一个自变量 + 一个明确的可比对照）

### 实验一：结构描述（描述，不下结论）

* 指标：入/出度分布（互补累积，log-log）、弱连通分量、度同配性、**依赖深度**分布、Gini。
* 只做描述。按课程提醒：**长尾外观不足以证明幂律**，本项目不做幂律断言。

### 实验二：级联影响面与瓶颈分数（对应 RQ1、RQ2）

| 指标 | "重要"的含义 | 计算口径 |
|---|---|---|
| `n_direct_dependents`（入度） | 直接连接多 | 直接边计数 |
| **`n_transitive_dependents`** | **被最多包间接依赖**（题目要求） | 已解析闭包口径，**精确** |
| `cascade_depth` | 级联往上最多爬几跳 | DAG 上反向最长路 DP |
| **`reverse_pagerank`** | **递归的"影响上游"能力**（题目要求） | 反向图上 PageRank |
| `betweenness` | 更多最短路经过（题目要求"介数中心性"） | k 点采样近似，报告 k 与稳定性 |
| `kcore` | 处在核心层 | 无向投影 k-core |
| `weighted_exposure` | 真实安装量暴露 | 传递依赖者下载量之和 |

* **对照**：指标两两 Spearman ρ（图 4）。若某个更贵的指标与更便宜的指标 ρ≈1，就说明它没有增加信息。
* **稳健性**：介数的采样 k 与随机种子；见 `t21` 相关表。

### 实验三：结构口径 vs 版本约束感知口径（对应 RQ3，本项目的核心贡献）

这是把题目里"**漏洞传播规则需要自己定义**"这句话落到实处的地方。定义两条规则：

**规则 S（结构上界）**：S 的传递闭包里出现 V ⇒ S 受 V 的漏洞影响。
**规则 V（版本约束感知）**：S 对 V 的**解析版本**落在该 advisory 的影响区间内 ⇒ S 真的受影响（该判定的材料来自 deps.dev 的已解析闭包 + OSV 的版本区间）。

* **自变量**：判定规则（S vs V）。
* **因变量**：受影响包数、受影响下载量、过近似倍数。
* **对照 / 去混杂**：过近似倍数 vs "依赖者中已解析到修复版本之后的比例"（机制分解，图 6）。
  这把"高估"从一个现象变成一个**有名字的机制**，而不是"扫描器不准"。

### 实验四：韧性情景（对应 RQ4）

* **自变量**：移除策略 × 移除比例 q；以及失效规则（AND / OR）。
* **策略**：随机、按入度、按传递依赖者、按反向 PageRank、按介数、按 k-core、按下载量。
* **规则 A（AND，软件真实语义）**：任一直接依赖坏 ⇒ 包坏。⇒ 失败集合 = 被移除集合的**反向可达并集**。
* **规则 B（OR，食物网语义）**：全部直接依赖坏 ⇒ 包坏。⇒ 用"存活依赖计数 + 队列"迭代，O(V+E)。
* **评价指标（三个，故意用三个）**：
  1. `S(q)` = 仍完全可用的种子包比例（**断崖型**指标）；
  2. `availability(q)` = 平均仍可用的闭包成员比例（**连续型**指标）；
  3. `LCC(q)` = 剩余网络最大弱连通分量份额（**与课程地铁案例同口径**，便于横向对话）。
* **控制条件**：同一原始网络、同一移除比例、同一排序（初始固定，见下）、同一随机种子集合。
* **排序更新协议**（课程"补充协议"）：本项目**按初始网络固定排序**（可复现、无路径依赖），
  并在 `t23_adaptive_check` 中给出"每步重算"的敏感性对照。
* **重复**：随机策略重复 30 次，报告均值 ± 标准差与种子。

### 情景对照：修复 vs 移除（题目"可做方向"第 3 条）

* **情景 P（修复）**：k 个瓶颈包获得安全修复 ⇒ 它们不再是漏洞源；依赖结构不变。
* **情景 R（移除）**：k 个瓶颈包从注册表消失 ⇒ 其所有传递依赖者无法构建。
* **关键洞察（预期）**：两者"暴露量下降"的数值可能接近，但**含义完全相反**——
  情景 R 的"暴露下降"是因为受影响者自己已经死了。所以必须同时报告可用性。
  这是本项目在方法论上的一个提醒：**只报一个指标会给出反向的政策结论**。

### 对照实验：保度序列零模型（排除"仅由度分布导致"这一替代解释）

* **做法**：有向双边交换（double edge swap），**精确保持每个节点入度与出度不变**，只随机化"谁连谁"。
* **检验**：反向可达集分布（KS 检验、max / p99 / Gini）、`S(q)` 曲线。
* **要排除的解释**：级联重尾只是度分布重尾的算术后果，这个生态并不特殊。
* **注意**：零模型允许出现环（"v 坏 ⇒ 所有传递依赖者坏"这条规则不需要无环），
  因此我们只在零模型上报告 AND 规则。

### 验证实验（回答"以你目前的方法，能看到什么？"）

1. **软信息检验**：只用最便宜的入度，能否预测最贵口径（版本感知真实受影响包数）？报告 bootstrap 95% CI。
2. **时间外推检验**：结构指标固定在**当前**快照，把 advisory 按披露年份切前/后两段，看 ρ 是否稳定。
   ⇒ 检验"固定时间切片"这一假设的稳健性。
3. **独立事件维度**：结构瓶颈分数 vs 该包历史 advisory 数量（一个完全独立于拓扑的维度）。
   ⇒ 识别"结构关键 + 历史多灾"的双重高风险包（图 11 的右上象限）。

## 6. 可靠性方案（对应课程"如何判断结果是否可靠"）

| 检查项 | 本项目的做法 |
|---|---|
| 随机种子 | 所有随机过程显式带 seed（配置里固定）；随机移除重复 30 次并报告波动带 |
| 误差分析 | 随机曲线画 ±1 s.d. 带；相关系数报 bootstrap 95% CI；介数报采样 k |
| 敏感性 | 介数采样 k、PageRank α、移除比例网格、排序是否重算，都作为独立参数在配置中可改 |
| 稳健性 | 换口径（闭包口径 vs 图口径）、换数据子集（只算榜内）、换规则（AND/OR）、换网络（零模型），看结论是否存活 |
| 数据质量 | 解析失败的版本数、闭包无法解析的包数、图/闭包口径差异，全部单独记账，不静默丢弃 |

## 7. 工具链与可复现

```
config/config.yaml          唯一参数真源（时间切片、口径、实验参数、随机种子）
src/01,02                   数据获取（原始文件 + 失败记录 + 断点续跑）
src/10                      网络构建 + 数据质量记账
src/20..25                  实验一..四 + 对照 + 验证
src/30                      图表
results/tables, figures     所有中间结果与图
report/                     报告与答辩材料
run_all.ps1                 一键复现
```

* 依赖：Python 3.13 + `networkx / pandas / numpy / scipy / matplotlib / packaging`（其余标准库）。
* 数据来源全部公开、无需密钥：PyPI 下载量榜（hugovk 镜像 pypistats）、
  deps.dev v3 API（Google osv-scanner 团队）、OSV.dev PyPI 漏洞库打包。
* 原始文件保存 + 下载日期记录 + 逐包版本号落盘 ⇒ 可逐包重建切片。
